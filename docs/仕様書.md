# 店長ダッシュボード 仕様書

最終更新: 2026-11-11

TOHO池袋店（パチスロ304台：20スロ144台・5スロ112台・2スロ48台）の店長が、日々の予実・設定投入・
機種の実績・経費を1か所で見るためのWebアプリ。この文書は「何ができて、データがどこにあり、
壊れたときどう戻すか」をまとめたもの。開発時の細かい注意は `CLAUDE.md` にある。

---

## 1. 全体のしくみ

| 項目 | 内容 |
|---|---|
| 画面 | 素のHTML/CSS/JavaScript（ESモジュール）。ビルド工程なし。書いたコードがそのまま動く |
| 配信 | GitHub Pages。`main` ブランチに入ると数分で本番に出る |
| データ | Supabase（PostgreSQL）。認証必須（共有アカウント1つ、画面ではパスワードだけ入れる） |
| 外部取得 | Supabase Edge Functions：`payout-fetch`（出玉率のWeb取得）、`shindai-fetch`（周辺店の新台） |
| 更新の届き方 | `sw.js` がネットワーク優先で配信。再読み込みすれば最新になる |
| オフライン | Supabaseに繋がらないと各タブは「表示できませんでした（通信）」を出す。データの閲覧・保存はできない |

リポジトリに営業データは入っていない。店舗固有の値（店舗ID・台番の初期値・島図の見た目調整）は
`src/core/config.js` にある。

## 2. 画面（タブ）

| タブ | 何をする画面か | 元になるデータ |
|---|---|---|
| 予実 | 月・年度の計画と実績、達成率、着地見込み、日別の表とグラフ、日報、目標からの計画作成 | 月計画表Excel／日別入力 |
| 島図・設定 | 島図の上で台ごとに設定を置き、予想粗利と計画比を見る。日ごとに保存。印刷（A4横・表1F/裏BF） | 島図Excel・台別データ・出玉率 |
| 機種分析 | 台ごとのアウト・玉単価・台粗利をレート内の高低で色分け、ランク付け | 台別データ |
| 出玉率 | 機種×設定1〜6の機械割を管理。シミュレーターが使う | 出玉率表・機種DB・Web |
| 新台 | 周辺店の新台入替を日ごとに追う | Edge Function が自動取得 |
| 経費 | 月次会議サマリー（損益・経費明細・途中経過・4店比較・所見）と月次の推移グラフ | 会議サマリーExcel・会議資料 |
| 取込 | 資料の取込口と取込履歴、島図の入替履歴・控え | — |
| 設定 | 区分（レート）と台番の対応、バックアップ | — |

タブの直下に常に出るもの:
- **鮮度表示**（左）：日次実績・台別データ・月次経費がいつまで入っているか。古くなると黄・赤で知らせる
- **📂 取込**（右）：どのタブからでも資料を入れられる。取り込めたら窓は自動で閉じる（注意が出たときだけ開いたまま）

### 見た目の決まり（全タブ共通）

- 文字の大きさは6種類だけ（`assets/css/theme.css` の `--fs-*`）：タイトル24／見出し17／本文16／列の多い表15／補足14／要点の数字38（添える比較は20）。
  島図のマスの中だけは例外
- 主色は青（選択中のタブ・主ボタン・入力中の枠）。**赤は未達・警告・消す操作だけ**
- 売上＝青、粗利＝緑。達成は 緑（100%以上）／黄（90%以上）／赤（未満）
- 各タブは上から「タイトルと操作 → 要点の数字 → グラフ → 表」の順に並べる
- 見た目は1種類（ドラクエ風テーマは廃止）

## 3. 取込

### 3.1 入口は1つ

取込タブの大きな枠、各タブ右上の「📂 取込」、画面のどこかへのドラッグ。どれも同じ処理で、
**ファイルの中身を見て資料の種類を判定する**。判定に自信が無いときは先頭の数行を見せて選んでもらう。

対応形式：CSV（Shift_JIS・UTF-8）、タブ区切り、Excel（xlsx・xls・xlsm・ods）、PDF（会議資料のみ）。

### 3.2 資料の種類と判定の手がかり

| 種類 | 手がかり | 入る先 | 取込前の確認 |
|---|---|---|---|
| 台別データ（K-TACs 遊技台個別） | 「台番号」「投入」などの列 | 機種分析・島図・出玉率の機種一覧 | 区分に入らない台番があれば止める。期間が無ければ聞く |
| 島図Excel | 「島図」「設定表」シート、「1F/BFフロア」の見出し | 台のレイアウト・設備・機種 | 読めた台数と今の台数を並べて表示。2割以上減るなら赤字で確認 |
| 月計画表Excel | 「◯月」のシートとレートの見出し | 予実（計画・実績・台数） | 書き込む期間と区分別の合計を表示 |
| 月次会議サマリーExcel | 表題「月次会議サマリー」 | 経費タブのサマリー＋月次推移 | なし（同じ月は上書き） |
| 損益・経費の表 | 費目名（総売上高・一般管理費…）と月の表記 | 経費タブの月次推移 | 読めた数字と単位（千円/円）を確認 |
| 出玉率表 | 「機種名」と「設定1〜6」の列 | 出玉率 | 店の機種への当て方を一覧で確認 |

ファイル以外の入れ方：損益は「表を貼り付けて取込」「手入力」（紙をスキャンしたPDFは機械では読めないため）。

### 3.3 読み方の決まり

- **列は名前で探す。** 位置では決めない。別の呼び方（アウト/IN、差枚、機械割…）も登録してある。
  見つからないときは画面で列を選んでもらい、同じ見出しの表は次から自動で読む（端末に記憶）
- **損益表は3つの形を読む。** 月が縦／月が横／1か月ぶん（予算・実績・前年が横に並び、月は表題）
- **予算を実績として入れない。** 予算と実績が並ぶ表は「実績」の列だけを使う。区別できなければ注意を出す
- **単位は聞く。** 千円か円かは資料によって違うので、確認画面で選んでから掛ける
- **空欄は空欄のまま。** 読めなかった費目で既存の値を消さない。出玉率の空欄は「その設定は無い」の意味

### 3.4 島図の控えと戻し方

島図の取込は台のレイアウトと機種を丸ごと置き換える。置き換える前の状態を自動で控える（新しい順に5件）。
戻すには、取込直後の画面の「取り込む前の島図に戻す」か、取込タブ →「📅 島図の入替履歴」→「この島図に戻す」。
島図でないファイル（島図シートもフロアの見出しも無い）は取り込まない。

## 4. 各画面の決まりごと

### 4.1 予実
- いちばん上は要点の4枠（売上・粗利・粗利率・計画まであといくら）と、粗利の進み具合のバー。
  バーは店全体で1本、区分を色でつなぎ、右端が計画。黒い線が「実績のある日までの計画」
- グラフは2つ：計画との差の累計（0より上＝貯金・下＝借金）と、日別の粗利を区分の色で積み上げた棒（横線＝その日の計画）
- 計画＝台あたりアウト × 台数 × 単価 × 粗利率。実績＝売上・粗利・台あたりアウトを入力
- **達成率は、実績の入っている日の計画と比べる。** 月の途中で1か月ぶんの計画と比べない
- **前年比も日をそろえる。** 今年実績のある日にちだけで前年を集計する
- 未入力の日は0として描かない（売上ゼロの日に見えるため）
- 日別入力は打ってから0.7秒後に自動保存。保存に失敗した入力は捨てずに残し、右上に「⚠ 未保存」を出す。
  保存待ちがあるままタブを閉じようとすると確認が出る

### 4.2 島図・設定（設定投入シミュレーター）
- 設定は日ごとに保存する。**保存の無い日は、それより前の最新の保存を引き継ぐ**（実機は触らなければ設定が残る）
- 据え置き指定の台は一括操作の対象外。個別タップでは変えられる
- 「全台を最低設定に戻す」は画面上だけ。以降の日の保存ごと断ち切るのは「この日から仕切り直す」
- 未保存の変更があるまま日付を移るときは確認する
- 出玉率が空欄の設定は割り当てない。設定1でパネルが消える機種は最低設定2（出玉率タブで指定）

### 4.3 機種分析
- 色とランクは同じレートの中での高低で決める
- ランクは A〜E：同じレートの中で、アウト・玉単価・台粗利それぞれの位置（何%目か）を平均した点数で並べ、
  上位10%＝A／10〜30%＝B／30〜70%＝C／70〜90%＝D／下位10%＝E。文字色は A赤・Bオレンジ・C黄・D緑・E青
- ヒートのセルは角を丸めた箱（6px）、区分は同じ高さの色の正方形に数字
- 全区分・機種平均はレートごとにまとめ、レートの境目に色の線と見出し（台数・機種数）を入れる
- 機種平均：同じ機種・同じレートの台をまとめる。アウト・台粗利は台の平均、玉単価・利益率は合計どうしの割り算。
  ランクも機種どうしで付ける（機種が10未満のレートではAが出ないことがある）
- 機種名は台別データのままのフルネーム（島図だけはマスが狭いので短縮）

### 4.4 出玉率
出典の優先順：**📄 出玉率表（店長の表）＞ 📚 機種DB（同梱）＞ 🌐 Web（一撃・DMM）＞ タイプ既定値**。
- 出玉率表は取り込むと丸ごと保存され、島図の入替で入った新しい機種も表から先に埋める
- 店の機種名は型式名（`S/新ﾊﾅﾋﾞR/HA`）のことが多いので、機種DBを経由して通称に当てる
- **末尾の番号が違う機種は自動で当てない**（マイジャグラーⅥとV、ゴーゴージャグラー3と2）
- 「参照するファイル」：PCのChrome/Edgeで一度ファイルを選ぶと、タブを開くたびに更新を確かめて反映する。
  ブラウザは `D:\…` の場所を直接は読めないので、選ぶ操作が1回要る。設定はその端末のそのブラウザだけ

### 4.5 経費
- 会議サマリーは会議の紙と同じ並びで出す。月次推移は `pl_month`（実績と予算）から描く
- 金額は内部ではすべて円。資料は千円なので取込のとき換算する

### 4.6 設定
- 台番と区分（レート）の対応はここで編集する。取込・島図・機種分析が同じ定義を見る
- バックアップは全データをJSONで保存。復元は同じキーの上書き（消してから入れ直す動作ではない）

## 5. データ

### 5.1 テーブル（Supabase）

| テーブル | 中身 | キー |
|---|---|---|
| `section_def` | 区分（20スロ等）。貸単価・並び順 | store_id + key |
| `machines_day` / `plan_day` / `actual_day` | 日別の台数／計画／実績 | store_id + ymd + section_id |
| `budget_year` / `budget_month` | 年間・月間の目標 | store_id + fy(+month) + section_id |
| `snapshot_period` / `machine_snapshot` | 台別データの取込1回ぶんと、その台ごとの数字 | id ／ period_id + dai_no |
| `layout_cell` / `fixture` | 島図の台の位置／設備（トイレ・出入口等） | store_id + dai_no ／ id |
| `model_spec` | 機種×設定の出玉率と出典 | model_name + setting |
| `sim_session` | 設定投入の保存（1日1行） | id（target_date で引く） |
| `pl_month` | 月次の損益・経費（実績・予算） | store_id + ym + kind |
| `shindai_shop` / `shindai_snapshot` | 新台タブの対象店と日次の取得結果 | — |
| `import_log` | 取込の記録 | id |
| `app_setting` | 下の表の設定類（JSON） | store_id + key |

定義は `supabase/migrations/`。`sim_comment`・`poster` は定義だけ残っていて使っていない。

### 5.2 `app_setting` のキー

| キー | 中身 |
|---|---|
| `dai_ranges` | 台番 → 区分の対応 |
| `island_models` | 台番 → 機種名（今の配置） |
| `island_meta` | 島図の適用開始日と入替履歴 |
| `island_backups` | 島図の控え（最大5件） |
| `payout_table` | 取り込んだ出玉率表（丸ごと） |
| `settei_types` / `settei_min` / `settei_exchange` | 機種のタイプ／最低設定／貸出・交換枚数 |
| `dmm_map` | 機種 → Web取得元のID |
| `meeting:YYYY-MM` | 月次会議サマリー（月ごと） |
| `shindai_calendar` | 新台タブの表示設定 |
| `capex_*` | 削除した増台計画タブの残り（使っていない） |

### 5.3 端末（ブラウザ）にだけあるもの

取込で選んだ列の対応、出玉率表の参照ファイル、新台タブの表示状態。
PCとスマホで共有されず、ブラウザのデータを消すと消える（消えても選び直せば済むものだけ）。

## 6. 困ったとき

| 症状 | 対処 |
|---|---|
| 修正が画面に出ない | 再読み込み（PCは Ctrl+Shift+R）。数分待ってもう一度 |
| 「◯◯を表示できませんでした」 | 通信の案内なら電波を確認して「もう一度開く」。それ以外は表示された文をそのまま開発担当へ |
| 右上が「⚠ 未保存」 | 通信が戻ってから別の欄を1つ入力するか、入力画面を閉じる（そのとき保存し直す）。消えるまでタブを閉じない |
| 島図が崩れた | 取込タブ →「📅 島図の入替履歴」→「この島図に戻す」。控えが無ければ正しい島図Excelを入れ直す |
| 取込で種類を間違えられた | 取込タブ →「種類を指定して入れる」から入れる |
| 取込で列が読めない | 出てくる画面で列を選ぶ（次から自動）。うまくいかなければファイルを開発担当へ |
| 出玉率が違う機種に当たった | 出玉率タブ →「保存済みの表を機種に当て直す」で選び直す。手で直した値は「保存」で確定 |
| データを丸ごと守りたい | 設定タブ →「バックアップを保存(JSON)」。月1回が目安 |

## 7. 開発と確認

- 作業ブランチで直し、PRを作って `main` にマージすると本番に出る。`main` へ直接は書かない
- CIは無い。コミット前に次を通す（構文・importの照合・機種DBのテスト・全タブの描画）:

```bash
sh tools/check/run.sh
```

- 画面の確認はSupabaseの代わりにブラウザ内保存で動かして行う（`tools/check/smoke.mjs` が自動でやる）。
  本番のSupabaseへの保存は開発環境からは確かめられないので、マージ後に本番で確認する
- 機種DB（`pachislot-db/`）の決まり：推測で数字を作らない／出典URLの無い数字を入れない／
  スクレイピングは robots.txt を確認し同一ホスト2.5秒間隔

### フォルダ

```
index.html            入口
assets/css            見た目（theme.css が色と文字の大きさ、components.css が共通の部品）
src/core              ルーター・DB窓口(repo.js)・認証・自動保存・鮮度表示・取込ボタン・設定値
src/features/<タブ>   各タブの画面
src/import            ファイルの読み取り（形式をそろえる anyTable.js、種類の判定 detect.js、各資料の読み方）
src/calc              集計（予実）・ヒートの色
src/util              日付・書式・CSV・台番の範囲
src/data              機種DBの書き出し（payout-db.json）
src/lib               同梱ライブラリ（SheetJS・supabase-js）
supabase/             テーブル定義と Edge Functions
pachislot-db/         機種データベース（収集スクリプトと原本）
tools/check           コミット前の確認
tools/pdfscan         スキャンPDFを画像に戻す道具
docs/                 この仕様書
```

### まだ出来ていない・気をつける点

- 本番データの自動バックアップは無い（設定タブから手動）
- 予実の集計は店舗の全期間のデータを毎回読む。年数が増えて遅くなったら期間で絞る
- 島図の見た目調整（`config.js` の `ISLAND_TWEAKS` など）は台番の範囲で書いてあり、
  コーナーの入替で台番が変わったらコードの修正が要る（取込時に食い違いを知らせる）
- 多店舗（川越・幕張・要町）には未対応。店舗IDは1つ固定
- ルート直下の `island-parse-test.html` は開発用の確認ページ
- 見た目の統一は予実タブから進めている。他のタブには画面ごとの直書きの大きさ・色がまだ残っている
