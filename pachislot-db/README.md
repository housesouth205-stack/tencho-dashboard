# パチスロ機種データベース

日本国内で稼働中のパチスロ／スマスロ機種の出率（設定1〜6）とコイン単価を、
出典付きで統一フォーマット化するデータベース。

**現在の状態: 全件取得フェーズ完了（データ取得日 2026-08-13）。**

## 対象と情報源

### 対象範囲

DMMぱちタウンのパチスロ機種一覧を **導入開始日 2018-02-01（6号機の規則施行日）以降** まで遡り、
機械的に列挙したものを候補とする。そこから **P-WORLDの機種ページの「タイプ」欄** を読んで
規則区分を確定させ、スマスロ／6号機系だけを残す。

6号機の規則は改正のたびに 6.1〜6.6号機 と枝番で呼ばれ、P-WORLDもその粒度で表記する。
いずれも6号機の系列なので、**6号機と 6.N号機 はまとめて対象**とする
（6.5号機だけを特別扱いすると6.1号機52機種・6.2号機35機種などが理由なく抜けるため）。
除外したのは5号機の87機種のみ。

導入年から号機を推定することはしない。タイプ欄を確認できなかった42機種は、
削除せずに残したうえで現行判定を「現行判定要確認」にし、備考に理由を書く。

内訳: スマスロ202／6号機158／6.5号機75／6.1号機52／6.2号機35／6.4号機6／6.6号機1／不明42。

パチ7は655ページを取得したが、出玉率をスペック行として載せているのは58機種だけだった

設定2〜5まで含めて突き合わせができる。DMMぱちタウンとパチ7は範囲表記しか持たないため、
**設定1と設定6の照合にのみ使う**。

### 現行判定の根拠

P-WORLDの機種ページに掲載されている **設置店舗数**（例:「【設置店4,853店舗】」）を根拠にする。

- 設置店舗数の記載があり1店舗以上 → **現行**（店舗数と調査日を備考に記録）
- 記載なし／0店舗 → **現行判定要確認**

導入年や号機からの推定は行わない。

## パイプライン

```bash
# 0. 到達可否と必要モジュールの確認
python3 scripts/check_egress.py

# 1. 抽出ロジックの検証（オフライン）
python3 scripts/test_extract.py     # HTML抽出 13ケース
python3 scripts/test_merge.py       # 照合ルール 13ケース

# 2. 対象機種一覧の作成（一覧ページからの機械的な列挙）
python3 scripts/enumerate_targets.py     # → data/targets.json

# 3. 情報源ごとの生データ取得（キャッシュされるので再実行でサイトに再アクセスしない）
python3 scripts/collect.py               # → candidates/collected.json

# 4. 照合して反映
python3 scripts/merge_candidates.py      # → data/machines.json

# 5. CSV / Excel / 品質レポートの生成
python3 scripts/build_database.py        # → output/
```

`candidates/` は情報源ごとの生データ置き場で、`data/machines.json` へは
`merge_candidates.py` の照合を必ず通す。機械抽出をそのまま正としない。

### 依存パッケージ

**`requests` のみ。** この環境ではパッケージレジストリ（pypi.org / files.pythonhosted.org /
archive.ubuntu.com）がegressで遮断されており `pip` も `apt` も使えないため、
`pandas` / `openpyxl` / `beautifulsoup4` / `lxml` への依存は標準ライブラリ実装に置き換えてある。

- `minihtml.py` — `<table>` をセルの二次元配列として取り出す／文書テキストを取り出す。
  実サイトに多い `</td>` `</tr>` の閉じ忘れ、入れ子テーブル、`script`/`style` に対応。
- `minixlsx.py` — xlsx は ZIP に XML を詰めた形式なので `zipfile` で直接生成する。
  ヘッダ書式・ウィンドウ枠固定・オートフィルタ・列幅・数値セルに対応。

置き換え後のCSV出力は pandas 版とバイト単位で一致することを確認済み。

## データ取得ルール

1. **推測禁止。** 設定2〜5の内挿、コイン単価の推定、メーカー・機種タイプの推測、
   欠損値の平均補完、他機種からの類推、旧機種データの流用 — いずれも行わない。
2. 範囲表記（例「97.0〜113.0%」）しか得られない場合、**設定1と設定6のみ**記録し、設定2〜5は空欄。
   `fetch_specs.py` の表抽出は範囲表記を意図的に捨てる実装になっている
   （表のセルに入った範囲を特定の設定値として取り込まないための担保）。
   範囲から設定1・6を取るのは `sources.parse_rate_range` の専用経路だけで、
   そこから設定2〜5に広げることはしない。
3. 数値は情報源に**明示されていたものだけ**を記録。
4. 出典URLの無い数値は記録しない。
5. 情報源間で数値が食い違う場合、平均・選択を行わず**全情報源の出典を保存**して「要確認」とする。
6. 現行機か曖昧な機種は削除せず、現行判定を「現行判定要確認」にする。
7. 取得できなかった機種は黙って除外せず、未取得機種シートに理由・試した情報源・再調査要否を残す。

### 食い違いが起きたときのセルの値について

ルール5の「選択もしない」を文字どおり守るとセルが空になり、情報が失われる。
そこで本データベースでは次のように扱い、判断の跡を全て残す方針を採った。

- セルには**設定ごとの表を持つ情報源**（スロベース／ななプレス）の値を入れる。
  範囲表記の両端から割り出した値より、設定ごとに掲載された値のほうが細かいため。
- **どの情報源を採ったかを備考に明記**し、**他方の値と出典URLも備考・出典URL列に残す**。
- 信頼度は「要確認」に落とす。

平均は取らない。値を作り出すこともしない。読み手が両方の出典を辿って判断できる状態にする。

### 「その機種に存在する設定」の決め方

設定1・2・5・6しか無い機種がある（ディスクアップ2、戦国無双3など）。
ところが情報源によっては6段階の表を載せており、それをそのまま採ると
**実在しない設定3・4に数値が入ってしまう**。

そこで「値」とは別に「どの設定が並んでいたか」を情報源ごとに記録し、多数決で決める。

- 票として数えるのは、**3つ以上かつ中間設定（2〜5）を含む**申告だけ。
  設定1と6しか載せていない表は「設定2〜5が無い」という主張ではなく
  単に情報が薄いだけなので、票に入れない。
- パチ7は出玉率の値の条件（完全攻略時など）が揃わず数値としては採らないが、
  設定の並びは判断材料になるので票には入れる。
- 決まった顔ぶれに無い設定は、値が取れていても空欄に戻し、
  どの情報源が何を載せていたかを備考に残す。
- **票が並んだときは設定の少ない申告を採る。** 6段階の表は雛形のまま埋めた結果のことがあるが、
  中間設定を抜いた表はその機種に無いから抜いたと読むのが自然なため。
  退けた申告は必ず備考に残す。

この判定で **495機種の顔ぶれを確定**し、**16機種で実在しない設定の値を削除**した。
確定した顔ぶれはダッシュボードにも渡していて、機械割のレンジしか無い機種でも
存在しない設定を補間しないようにしている。

### 型式名から分かること

検定型式名の頭文字は媒体を表す。572機種で例外が無いことを確認した。

| 型式名の頭 | 意味 | 件数 |
|---|---|---|
| `L` / `LB` | スマスロ | 202（P-WORLDの規則区分と100%一致） |
| `S` | メダル機（6号機系） | 320（スマスロは1件も無い） |

これを使って、P-WORLDで規則区分を確認できなかった機種のメディア区分を、
推測ではなく型式名から補っている（メディア区分の不明が42件→15件）。

`LB` で始まる19機種はボーナス主体の **BT機**。P-WORLDは「Aタイプ」に寄せて
掲載しているが、実機の括りに合わせてBTとして分類している。

### 型式名と機種名

店舗の遊技台CSVは**機種名ではなく検定型式名**で入っていることが多い
（例: 店側の「S/新ﾊﾅﾋﾞR/HA」は型式名）。またサイト側の機種名と型式名が
食い違う機種もある（機種名「ぱちスロ ギャグダー」＝型式名「SギャグラーKB」）。

そのため型式名も機種名・別表記と同じ照合キーとして持たせている。
半角カナはNFKC正規化で吸収されるので、店側の表記のままでも一致する。

### 設定の補完について

同じ機種でも情報源ごとに載っている設定が違うことがある
（例: 片方が設定1〜6、もう片方が設定1・6のみ）。
このとき、**先に読んだ情報源が値を持っていない設定に限り**、別の情報源の値で埋める。
既にある値を上書きすることはない。補完した設定は
「設定Nは○○から補完」と備考に書き、両方の出典URLを残す。

## 情報源の優先順位

1. メーカー公式サイト・公式資料
2. DMMぱちタウン / パチ7 / パチマガスロマガ / P-WORLD / その他パチスロ専門解析サイト
3. その他の検索結果

**本バッチではメーカー公式サイトを情報源として使っていない。**
スペック（設定別機械割・コイン単価）を機械可読な形で掲載しているのが解析サイト側であり、
到達可能なメーカー公式サイトにはその掲載が確認できなかったため。
したがって信頼度「高」は**解析サイト2件以上の一致**によるもので、メーカー公式との照合ではない。

## 信頼度の基準

| 信頼度 | 条件 |
|---|---|
| 高 | 設定1と設定6の両方が2情報源以上で一致 |
| 中 | 一部の設定のみ複数情報源で一致、または設定1〜6を1情報源で完全取得（照合未達） |
| 低 | 範囲表記からの設定1・6のみ（1情報源） |
| 要確認 | 情報源間で数値が一致しない／出率を1件も取得できなかった |

READMEの元の基準では「条件が不明」も要確認としていたが、
出率条件を明記している情報源が少なく大半が要確認に倒れてしまうため、
**出率条件の不明は信頼度ではなく品質チェック（要確認シート）で扱う**ことにした。

## 出率条件について

機械割・出率には前提条件がある（メーカー発表値／完全攻略時／独自調査値／シミュレーション値など）。
数値と併せて条件も保存する方針だが、条件表記のあるページは限られる。
条件が読み取れない場合は「不明（条件表記未確認）」とし、品質チェックでフラグを立てる。

## コイン単価の定義

対象機種におけるホール側の1コインあたり利益。
本データベースでは **スロベースが掲載している値をそのまま記録**し、
併記されている前提（例:「約3.7円(設定1)」の「設定1」）を「コイン単価条件」に入れる。
条件の記載が無い場合は「条件表記なし」とする。

**回転数や機械割からの逆算は行わない。** 掲載が無い機種は空欄とし、備考に「コイン単価未確認」と記載する。

## データ品質チェック

`build_database.py` が毎回自動実行する。**異常を検出しても自動修正はせず、「要確認」シートに転記するのみ。**

今回の検出内訳（総数1,683件）:

| 件数 | 内容 |
|---|---|
| 522 | 出率条件が不明（条件を明記している情報源が少ない） |
| 519 | コイン単価未確認 |
| 289 | 出率欠損（設定2〜5が空欄、など） |
| 188 | 出率の情報源が1件のみ（照合未達） |
| 80 | 現行機かどうか不明 |
| 42 | 機種タイプ不明 |
| 13 | 出率を1件も取得できず |
| 4 | 設定間の出率が逆転している |
| 0 | メーカー名・機種タイプ・メディア区分の表記ゆれ |

「要確認」機種数が567件と多いのは、**1つでもフラグが立てば転記する設計**のため。
その大半は「コイン単価未確認」「出率条件が不明」で、出率の値そのものが疑わしい
という意味ではない。値の矛盾を示すのは「設定間の逆転」4件のみ。

- 機種名の重複（別表記の正規化衝突も検出。「L○○」「スマスロ○○」を同一視して照合）
- 設定1〜6の欠損
- 設定6が設定1より低い／設定間の逆転
- 出率が想定レンジ（80〜130%）外
- コイン単価が想定レンジ（0.5〜10円）外
- 出典URLの存在とスキーム妥当性
- 出率の情報源が1件のみ（照合未達）
- メーカー名・機種タイプ・メディア区分の表記ゆれ（正規化辞書未登録を検出）
- 出率条件・現行判定・メーカー・機種タイプの不明

### 設定間の逆転について

「設定6が設定1より低い」は異常だが、**設定間の逆転そのものは異常とは限らない**。
設定3を搭載しない機種や、設定4より設定5の機械割が低い機種は実在する。
本チェックは自動修正をせず要確認に転記するだけなので、そのまま残している。

## スクレイピングについて

- 各サイトの `robots.txt` を取得前に必ず確認し、Disallow のURLは取得しない
- `Crawl-delay` を尊重し、指定が無くても**同一ホストへのアクセス間隔は最低2.5秒**
- **並列アクセスは行わない**（同時に開くコネクションは常に1本）
- 取得したHTMLは `cache/` に保存し、再実行時はサイトへ再アクセスしない
- 規約・robots上問題のあるサイトは自動取得の対象外とし、代替情報源に切り替える

### 自動取得の対象外にしたサイト

| サイト | 理由 |
|---|---|
| `p-gabu.jp` | 到達はするが、robots.txt を含む全リクエストに 403 を返すため |
| `cs62.cs-plaza.com`（パチマガスロマガ） | スペック表がHTMLに含まれず、機種ページから設定別機械割を取得できなかったため |
| `www.daito.co.jp` | HTTPSで応答しない。現行サイトの `www.daitogiken.com` を参照 |
| `chonborista.com`（ちょんぼりすた） | 機種別ではなく記事単位の構成で、設定別機械割の表を持たないため |
| `1geki.jp`（一撃） | 同上 |

## 注意事項

- 本データベースは**情報整理を目的とした参考資料**であり、出玉・収支を保証するものではない。
- 出率（機械割）は前提条件により変動する。条件を確認せずに数値だけを比較しないこと。
- 各数値の一次情報は出典URL先にある。重要な判断の前には出典元の確認を推奨する。
- メーカー公式との照合は行えていない。信頼度「高」も解析サイト同士の一致にとどまる。
