### 解消方法：cloud environment の許可ドメイン追加

1. [claude.ai/code](https://claude.ai/code) で、**メッセージ入力欄の上の行**にあるクラウドアイコン
   （現在の環境名が表示されている）をクリックして環境セレクタを開く。
   専用の設定ページも直接URLも存在しない。
2. 対象環境にマウスを乗せて右側の**歯車アイコン**を選ぶ（新規なら **Add cloud environment**）。
3. ダイアログの **Network access** を **Custom** にする
   （既定は **Trusted** = パッケージレジストリ・GitHub等の既定リストのみ）。
4. **Allowed domains** に1行1ドメインで下記を貼る。書式は**ホスト名のみ**で、
   スキーム・ポート・パスは付けない。`*.example.com` はサブドメイン全体にマッチする。
5. **「Also include default list of common package managers」に必ずチェック。**
   外すと下記リスト以外が全て遮断され、`pip install` 等が動かなくなる。
   **2026-08-13時点の環境「設定出率」ではここが未チェックの状態**で、`pypi.org` /
   `files.pythonhosted.org` / `archive.ubuntu.com` がいずれも403。`pandas` `openpyxl`
   `beautifulsoup4` `lxml` を導入できず、`fetch_specs.py` と `build_database.py` が実行不能。
   ドメイン追加だけでは解決しないので、**このチェックを必ず入れ直すこと。**
6. 保存後、**新しいセッションを開始する。実行中のセッションは環境設定を読み直さない。**

## 全件取得フェーズの手順（egress解放後）

```bash
# 1. 許可状況の確認。全ドメインが ✓ になるまで先に進まない
python3 scripts/check_egress.py

# 2. 抽出ロジックの健全性確認
python3 scripts/test_extract.py

# 3. 対象機種一覧の作成（一覧ページから機械的に列挙）
#    p-town.dmm.com/machines/slot, /machines/smart_slot 等

# 4. スペック取得＋抽出（キャッシュされるので再実行してもサイトに再アクセスしない）
python3 scripts/fetch_specs.py --urls data/target_urls.txt

# 5. candidates/extracted.json を照合してから data/machines.json へ反映
#    ※ 自動マージはしない。2情報源で一致したものだけ信頼度「高」にする

# 6. 再ビルド
python3 scripts/build_database.py
```

`fetch_specs.py` の設計方針:

- **robots.txt を必ず確認**し、Disallow のURLは取得しない（代替情報源に切り替える）
- `Crawl-delay` を尊重し、指定が無くても**最低2.5秒**間隔。並列アクセスは行わない
- 取得したHTMLは `cache/` に保存し、**再実行時はサイトへ再アクセスしない**
- 範囲表記（「97.7〜114.9%」）は個別設定値ではないため**意図的に捨てる**。
  設定2〜5を範囲から内挿しないための実装上の担保
- 抽出結果は `candidates/` に出すだけで `data/machines.json` には自動マージしない。
  機械抽出をそのまま正とせず、必ず照合工程を挟む

## データ取得ルール

1. **推測禁止。** 設定2〜5の内挿、コイン単価の推定、メーカー・機種タイプの推測、
   欠損値の平均補完、他機種からの類推、旧機種データの流用 — いずれも行わない。
2. 範囲表記（例「97.0〜113.0%」）しか得られない場合、**設定1と設定6のみ**記録し、設定2〜5は空欄。
3. 数値は検索結果に**明示されていたものだけ**を記録。要約AIの単独記述で一次確認が取れないものは、
   値を記録した上で信頼度を「要確認」に落とし、備考に理由を書く。
4. 出典URLの無い数値は記録しない。
5. 情報源間で数値が食い違う場合、平均・選択を行わず**両方の出典を保存**して「要確認」とする。
6. 現行機か曖昧な機種は削除せず、現行判定を「現行判定要確認」にする。

## 出率条件について

機械割・出率には前提条件がある（メーカー発表値／完全攻略時／フル攻略時／独自調査値／シミュレーション値など）。
数値だけでなく条件も保存する方針だが、**本バッチでは検索結果に条件表記が無く、
9機種すべて「不明（条件表記未確認）」**となった。一次ページを開ければ解消できる項目。

## コイン単価の定義

対象機種におけるホール側の1コインあたり利益。一般に「1000G回すのに必要な平均投資額 ÷ 3000枚」の考え方で語られる。
サイトにより算出前提（設定・回転数・期間）が異なるため、数値と併せて「コイン単価条件」に前提を記録する。
根拠が不明な場合は空欄とし、備考に「コイン単価未確認」と記載する。

## 信頼度の基準

| 信頼度 | 条件 |
|---|---|
| 高 | メーカー公式、または複数の信頼できる情報源で数値が一致 |
| 中 | 信頼できる専門サイト1〜2件で確認 |
| 低 | 1サイトのみ、または情報が不完全 |
| 要確認 | 情報源間で数値が一致しない、条件が不明、異常値検出 |

**注意**: 本バッチは一次ページ未検証のため、**「高」は1件も付与していない**。
最高でも「中」（設定1〜6を全取得できた1機種のみ）。

## データ品質チェック

`build_database.py` が毎回自動実行する。**異常を検出しても自動修正はせず、「要確認」シートに転記するのみ。**

- 機種名の重複（別表記の正規化衝突も検出。「L○○」「スマスロ○○」を同一視して照合）
- 設定1〜6の欠損
- 設定6が設定1より低い／設定間の逆転
- 出率が想定レンジ（80〜130%）外
- コイン単価が想定レンジ（0.5〜10円）外
- 出典URLの存在とスキーム妥当性
- 出率の情報源が1件のみ（照合未達）
- メーカー名・機種タイプ・メディア区分の表記ゆれ（正規化辞書未登録を検出）
- 出率条件・現行判定・メーカー・機種タイプの不明

## スクレイピングについて

本バッチでは自動スクレイピングを一切行っていない（そもそも全ドメインがegressブロック）。
使用したのは検索APIのみで、各サイトへの直接アクセスは発生していない。

全件取得フェーズでegressが解放された場合は、以下を遵守する。

- 各サイトの `robots.txt` と利用規約を事前確認し、禁止されているサイトは自動取得の対象外にする
- リクエスト間隔を最低2〜3秒空ける
- 並列アクセスを行わない
- 規約上問題のあるサイトは代替情報源に切り替える

## 注意事項

- 本データベースは**情報整理を目的とした参考資料**であり、出玉・収支を保証するものではない。
- 出率（機械割）は前提条件により変動する。条件を確認せずに数値だけを比較しないこと。
- 各数値の一次情報は出典URL先にある。重要な判断の前には出典元の確認を推奨する。
- 現在のデータは**一次ページ未検証**であり、そのまま業務判断に用いるべきではない。
