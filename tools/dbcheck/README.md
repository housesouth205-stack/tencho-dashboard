# 本番の中身を読んで確認する道具

「CSVは取り込まれているか」「地代家賃は直ったか」「増台の台番は島図と合っているか」は、
画面を開かないと分からない。聞いて答えてもらうと1往復かかるうえ、聞き漏らすと
次のセッションにそのまま持ち越される（引き継ぎメモの「まだ確認できていないこと」は
だいたいこれ）。繋がる環境からこれを流せば、その場で全部答えが出る。

**読むだけ。1バイトも書かない。** 直すのは画面から。道具から書くと、検算も確認画面も
通らないまま本番のデータが変わる。

## 使い方

```bash
export DASH_PASSWORD='共有アカウントのパスワード'
python3 tools/dbcheck/check.py
```

接続先とログイン用メールは `src/core/config.js` から読む（書き写すと片方だけ古くなる）。
パスワードは環境変数からしか受け取らない。引数にすると `ps` と履歴に残り、
チャットに貼るとセッションのログに残る。出力にも出さない。

## 出るもの

- **RLSの穴**: 未ログイン（anonキーだけ）で読めるテーブルがないか。anonキーは
  GitHub Pages のソースに露出しているので、読めたら誰でも読める。
  `pl_month` は `0002_auth_rls.sql` のテーブル一覧に入っていない（後から足したテーブル）
  ので、ここが特に怪しい
- **月次の損益・経費**: 月ごとの数字を千円で。資料と同じ検算3つ（内訳合計＝一般管理費 /
  総売上高−売上原価＝売上総利益 / 売上総利益−一般管理費＝営業利益）を全月にかける。
  地代家賃は毎月4,000千円で固定のはずなので、ばらついていたら資料の行ずれを疑う
- **島図**: 階ごとの台数と台番の範囲
- **増台計画**: 単価台帳（総額÷数量＝単価）と工事回。工事回の台番が島図に無い、
  台数と台番の数が合わない、を指摘する

## 繋がらないとき

この環境のネットワークは許可したホストにしか出られない。Supabaseのホストが
許可されていないと、CONNECT が 403 で拒否される（スクリプトがそう表示する）。
環境設定のネットワークアクセスにホストを足して、**新しいセッションを開く**こと
（ポリシーはコンテナ起動時に決まるので、途中で足しても効かない）。

外部ライブラリは使わない。パッケージレジストリに出られないため
（`pachislot-db` と同じ事情）。
